# Unity Save System

Две реализации системы сохранений для Unity. Выберите подходящую под свой проект.

---

## SaveSystem1 — Простая система на 3 слота

**Подходит для:** небольших проектов, начинающих разработчиков, когда нужна максимально читаемая реализация ровно с тремя слотами сохранений.

### Как работает

У каждого слота есть собственные переменные (`player1`, `player2`, `player3`, `act1`, `act2`, `act3`). Каждый слот сохраняется в отдельный JSON-файл на диске.

| Слот | Файл на диске |
|------|--------------|
| 1 | `savefile.json1` |
| 2 | `savefile.json2` |
| 3 | `savefile.json3` |

### Что сохраняется

- Имя игрока
- Флаги квестов: `fiveContractsAct`, `killForestBossAct`, `destrMonolythAct`, `killFinalBossAct` и другие
- Уровни построек: `tierMain`, `tierArchive`, `tierBarracks`, `tierStables`, `tierStorehouse`, `tierForge`, `tierArtifact`, `tierHerbalist`
- Ресурсы: `baseCoins`, `baseWood`, `baseStone`, `baseLeather`, `baseDiamond`

### Доступные методы

```csharp
SaveSystem1.ins.ActivePlayer(int playerSlot);  // Генерация данных и активация слота (1, 2 или 3)
SaveSystem1.ins.SaveInfo();                    // Сохранить активный слот
SaveSystem1.ins.LoadName1();                   // Загрузить слот 1 и сделать его активным
SaveSystem1.ins.LoadName2();                   // Загрузить слот 2 и сделать его активным
SaveSystem1.ins.LoadName3();                   // Загрузить слот 3 и сделать его активным
```

### Подключение

1. Создайте пустой GameObject в первой сцене (например, `SaveManager`)
2. Добавьте компонент `SaveSystem1`
3. Синглтон переживает смену сцен через `DontDestroyOnLoad`

### Настройка кнопок в Inspector

Для работы системы нужно три вида кнопок: генерация данных слота, сохранение и загрузка.

#### Кнопки генерации данных (по одной на каждый слот)

1. Создайте и выделите кнопку генерации данных 1 в Hierarchy
2. В компоненте `Button` нажмите `+` в `On Click ()`
3. Перетащите GameObject с компонентом `SaveSystem1` в поле объекта
4. Выберите `SaveSystem1 → ActivePlayer`
5. Впишите в поле номер слота (1)

Аналогично для слотов 2 и 3.

#### Кнопка сохранения (одна на весь UI)

Метод `SaveInfo` без параметров — привязывается напрямую:

1. Создайте и выделите кнопку сохранения в Hierarchy
2. В компоненте `Button` нажмите `+` в `On Click ()`
3. Перетащите GameObject с компонентом `SaveSystem1` в поле объекта
4. Выберите `SaveSystem1 → SaveInfo`

#### Кнопки загрузки (по одной на каждый слот)

Методы `LoadName1`, `LoadName2`, `LoadName3` без параметров — привязываются напрямую:

1. Создайте и выделите кнопку загрузки слота 1 в Hierarchy
2. В компоненте `Button` нажмите `+` в `On Click ()`
3. Перетащите GameObject с компонентом `SaveSystem1` в поле объекта
4. Выберите `SaveSystem1 → LoadName1`
5. Впишите в поле номер слота (1)

Аналогично для слотов 2 и 3: `LoadName2`, `LoadName3`.

### Чтение данных в других скриптах

```csharp
int coins = SaveSystem1.ins.baseCoins;
int tier  = SaveSystem1.ins.tierMain;
```

## SaveSystem2 — Масштабируемая система с произвольным количеством слотов

**Подходит для:** проектов, где количество слотов может меняться, или когда нужна более чистая архитектура на основе массивов.

### Как работает

Все данные хранятся в массивах, индексированных по номеру слота. Индексы слотов начинаются с **1** (индекс 0 не используется). Каждый слот сохраняется в отдельный JSON-файл.

| Слот | Файл на диске |
|------|--------------|
| 1 | `savefile_slot1.json` |
| 2 | `savefile_slot2.json` |
| N | `savefile_slotN.json` |

Чтобы изменить количество слотов, достаточно поменять одну константу:

```csharp
private const int realMaxSlots = 3; // измените на любое число
```

### Что сохраняется

Тот же набор полей, что и в SaveSystem1, но хранится в массивах с индексом по слоту.

### Доступные методы

```csharp
SaveSystem2.ins.ActivePlayer(int playerSlot);  // Генерация данных и активация слота (1..realMaxSlots)
SaveSystem2.ins.SaveInfo();                    // Сохранить активный слот
SaveSystem2.ins.SaveSlot(int slot);            // Сохранить конкретный слот по индексу
SaveSystem2.ins.LoadSlot(int slot);            // Загрузить конкретный слот по индексу
```

### Подключение

1. Создайте пустой GameObject в первой сцене (например, `GameManager`)
2. Добавьте компонент `SaveSystem2`
3. Синглтон переживает смену сцен через `DontDestroyOnLoad`

> **Важно:** все массивы инициализируются в `Awake()` через `InitArrays()`. Не полагайтесь на размеры массивов, выставленные в Inspector — Unity перезаписывает инициализаторы полей при десериализации, поэтому явная переинициализация в `Awake` обязательна.

### Настройка кнопок в Inspector

Для работы системы нужно три вида кнопок: генерация данных слота, сохранение и загрузка.

#### Кнопки генерации данных (по одной на каждый слот)

Метод `ActivePlayer` принимает номер слота — Inspector позволяет передать его напрямую:

1. Создайте и выделите кнопку генерации данных 1 в Hierarchy
2. В компоненте `Button` нажмите `+` в `On Click ()`
3. Перетащите GameObject с компонентом `SaveSystem2` в поле объекта
4. Выберите `SaveSystem2 → ActivePlayer`
5. Впишите в поле номер слота (1)

Аналогично для слотов 2, 3 и далее.

#### Кнопка сохранения (одна на весь UI)

Метод `SaveInfo` без параметров — привязывается напрямую:

1. Создайте и выделите кнопку сохранения в Hierarchy
2. В компоненте `Button` нажмите `+` в `On Click ()`
3. Перетащите GameObject с компонентом `SaveSystem2` в поле объекта
4. Выберите `SaveSystem2 → SaveInfo`

#### Кнопки загрузки (по одной на каждый слот)

Методы `LoadName1`, `LoadName2`, `LoadName3` без параметров — привязываются напрямую:

1. Создайте и выделите кнопку загрузки слота 1 в Hierarchy
2. В компоненте `Button` нажмите `+` в `On Click ()`
3. Перетащите GameObject с компонентом `SaveSystem1` в поле объекта
4. Выберите `SaveSystem1 → LoadName1`
5. Впишите в поле номер слота (1)

Аналогично для слотов 2 и 3: `LoadName2`, `LoadName3`.

### Чтение данных в других скриптах

```csharp
int activeSlot = SaveSystem2.ins.GetActiveSlot(); // возвращает 1, 2, 3... или -1 если нет активного
int coins = SaveSystem2.ins.guildCoins[activeSlot];
int tier  = SaveSystem2.ins.tierMain[activeSlot];
```

## Сравнение

| Параметр | SaveSystem1 | SaveSystem2 |
|---------|------------|-------------|
| Количество слотов | Фиксировано: 3 | Задаётся константой |
| Стиль кода | Явные переменные на каждый слот | Массивы с индексом по слоту |
| Добавить новый слот | Нужны новые переменные и методы | Изменить константу + добавить кнопки |
| Кнопка загрузки без скрипта | Да (`LoadName1/2/3`) | Нет (нужен `SlotButton2`) |
| Читаемость | Высокая | Средняя |
| Масштабируемость | Низкая | Высокая |
| Имена файлов сохранений | `savefile.json1/2/3` | `savefile_slot1.json` и т.д. |

## Расположение файлов сохранений

Файлы записываются в `Application.persistentDataPath`:

| Платформа | Путь |
|-----------|------|
| Windows | `%AppData%\..\LocalLow\<Company>\<Product>\` |
| macOS | `~/Library/Application Support/<Company>/<Product>/` |
| Linux | `~/.config/unity3d/<Company>/<Product>/` |
| Android | `/storage/emulated/0/Android/data/<package>/files/` |

---

## Примечания

- Обе системы используют **паттерн синглтон** (`ins`) и переживают смену сцен через `DontDestroyOnLoad`
- Данные сериализуются в **JSON** с помощью `JsonUtility`
- Активный слот автоматически сохраняется при выходе из приложения (`OnApplicationQuit`)
- В один момент времени **активен только один слот**
